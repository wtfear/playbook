# Specialty: Messaging Bots and Conversational Agents

> [!NOTE]
> **Candidate Practice / Proposed Scaffolding:** This document contains candidate material for research and evaluation. It does not constitute approved agency policy, mandatory instruction, or contractual commitment until formally reviewed and marked with `status: approved`.

---

## 1. When It Applies

- **Applies to:** Conversational bots, customer service automations, interactive notification systems, and transactional agents deployed on third-party messaging channels (WhatsApp Cloud API, Telegram Bot API, Slack Apps, Discord, SMS).
- **What Does NOT Apply:** Static web chat widgets that do not maintain asynchronous session state or connect to external messaging networks.

---

## 2. Must (Mandatory Minimum)

> *Status: [Pending Founder Decision]*
> 
> *The following subtopics represent candidate technical areas to research and evaluate. They do not constitute approved mandatory rules.*

- [ ] **Webhook Verification & Immediate Acknowledgement:** Responding to upstream platform webhook events immediately with an HTTP 200 OK within platform timeouts (<3 seconds) while offloading conversational processing to background queues.
- [ ] **Message Deduplication & Concurrency Handling:** Implementing cache-backed deduplication (candidate tool: Redis key locks) to prevent processing duplicate webhook deliveries caused by upstream platform retries.
- [ ] **Conversational Session State Management:** Storing multi-turn conversation context and user states in persistent, scalable key-value or document stores with explicit TTL expirations.
- [ ] **Human-in-the-Loop Handoff:** Designing graceful escalation paths that allow human support agents to pause bot execution and take over the conversation thread seamlessly.
- [ ] **Platform Rate Limiting & Quota Management:** Implementing client outbound throttling to comply with strict platform messaging tier limits and avoid automated phone number or app bans.

---

## 3. Should (Recommended Practice & Judgment)

- What message broker (e.g., Redis Streams, RabbitMQ, SQS) provides the lowest latency and operational overhead for routing asynchronous chat events?
- How should multimedia payloads (voice notes, images, PDFs) sent by users be sanitized, transcribed, or stored without leaking confidential PII?
- What metrics track conversational drop-off rates and user sentiment to measure bot efficacy?

---

## 4. Common Failure Modes

- **Infinite Bot-to-Bot Ping-Pong:** Permitting a messaging bot to respond to automated messages generated by another bot, exhausting API token budgets within minutes.
- **Webhook Timeout Retries:** Executing slow LLM completions synchronously inside the inbound webhook handler, causing messaging platforms to assume the server is down and hammer the endpoint with retries.
- **Account Suspension via Spam Flagging:** Broadcasting marketing messages outside approved platform template guidelines, triggering immediate carrier or WhatsApp account suspension.

---

## 5. Evidence That It's Done

- [ ] Automated integration test proving inbound webhook returns HTTP 200 within 500ms under simulated heavy LLM processing load.
- [ ] Idempotency test verifying identical message IDs sent twice result in exactly one outbound response.
- [ ] Human handoff trigger tested and confirmed to disable bot auto-responses until manually released.
