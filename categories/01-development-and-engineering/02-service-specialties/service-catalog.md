# Technical Service Catalog

> [!NOTE]
> **Candidate Practice / Proposed Scaffolding:** This document contains candidate material for research and evaluation. It does not constitute approved agency policy, mandatory instruction, or contractual commitment until formally reviewed and marked with `status: approved`.


## 1. Purpose
Provides a consolidated technical overview of potential technical service domains under evaluation by the engineering team, tracking activation readiness, core capabilities, and dependencies.

> [!NOTE]
> All services listed below maintain an **activation status of "unconfirmed"**. Commercial packaging and service approvals are governed by [`../../03-business-strategy-and-governance/`](../../03-business-strategy-and-governance/README.md).

## 2. Proposed Scope
- Overview of 8 candidate technical specialties.
- Evaluation criteria for advancing a specialty from "unconfirmed" to "active".
- Identification of shared foundational requirements versus domain-specific capabilities.

## 3. Applicability
Applies to engineering scoping discussions, technical capability planning, and sales feasibility reviews.

## 4. Candidate Service Capabilities Matrix

| Service Specialty | Candidate Domain | Activation Status | Delivery Complexity | Primary Shared Standards |
| :--- | :--- | :---: | :---: | :--- |
| **Web Applications & Websites** | Client portals, SaaS web apps, marketing sites | **Unconfirmed** | Moderate | UX/UI, Accessibility, Security, CI/CD |
| **Mobile Applications** | Cross-platform / native iOS & Android | **Unconfirmed** | High | API Engineering, Store Release, Security |
| **Backend APIs & Integrations** | REST, GraphQL, webhooks, microservices | **Unconfirmed** | Moderate | API Standards, Observability, Data |
| **Automation & Business Systems** | Workflow automations, ETL syncs, iPaaS | **Unconfirmed** | Moderate | Error Recovery, Idempotency, Secrets |
| **AI Applications & Agents** | LLM orchestration, RAG, agent workflows | **Unconfirmed** | High | AI Safeguards, Data Privacy, Testing |
| **Data Engineering & Analytics** | Data pipelines, modeling, BI reporting | **Unconfirmed** | High | Data Validation, Pipeline Quality, Security |
| **Cloud & Platform Engineering** | Cloud infrastructure, DevOps, IaC | **Unconfirmed** | High | Cloud Security, Secrets, Observability |
| **Desktop Applications** | Cross-platform utilities, desktop tools | **Unconfirmed** | Moderate | Code Signing, OS Permissions, Auto-update |

## 5. Questions to Research or Decide
- What minimum criteria (e.g., successful pilot, documented starter kit, proven lead engineer) are required to activate a specialty?
- Should the agency focus initially on a single specialized niche (e.g., B2B Workflow Automation) or maintain a broader full-stack web capability?

## 6. Candidate Evidence and Artifacts
- Technical readiness assessments for each specialty.
- Boilerplate starter repositories and architectural reference designs.

Collaborate with Business Strategy (Category 03) to select the initial pilot specialties.
